# Image Restoration

## Project Overview

This project implements an image restoration and super-resolution system designed to restore degraded grayscale input images and generate high-quality restored images.

The project includes the trained restoration model, FP32 and INT8 quantization artifacts, standalone inference and evaluation scripts, test data, restored outputs, and an FPGA/HLS-oriented implementation.

The model is designed with hardware-friendly operations and an eventual FPGA/HLS deployment in mind.

The complete project workflow is:

```
Data
  ↓
Model Design
  ↓
FP32 Training
  ↓
FP32 Baseline
  ↓
INT8 Quantization
  ↓
QAT INT8 Quantization
  ↓
Activation Calibration
  ↓
INT8 Verification
  ↓
HLS Implementation
  ↓
HLS Simulation / Synthesis
  ↓
FPGA Implementation and Evaluation

```

## Model Description

The model is designed for image restoration and super-resolution. It takes a degraded grayscale input image and processes it through a hardware-friendly restoration network to generate a restored high-resolution grayscale output image.

The model architecture consists of a head convolution, residual restoration blocks, channel expansion and reduction layers, nearest-neighbor upsampling, and a final output convolution followed by a sigmoid activation.

The model input is a **1 × 128 × 128 grayscale image**, and the model output is a **1 × 256 × 256 restored grayscale image**.

The input image resolution is **128 × 128**, and the output image resolution is **256 × 256**.

The main restoration pipeline is:

```
Input
  ↓
Head Conv
  ↓
RES1
  ↓
Expand Conv
  ↓
RES2
  ↓
Reduce Conv
  ↓
Nearest-Neighbor Upsampling
  ↓
RES3
  ↓
Tail Conv
  ↓
Sigmoid
  ↓
Output

```

Nearest-neighbor upsampling is used to maintain a simple and hardware-friendly implementation.

## Evaluation and Inference

The `run.py` script is the main script used to run inference with the trained restoration model.

The inference pipeline:

1. Reads the input `.npy` files.
2. Loads the trained model.

4. Runs the restoration model.
5. Performs the required postprocessing.
6. Saves the restored outputs to the `output/` directory.

Before running inference, make sure that the Python environment has been created, all dependencies have been installed, the required model files are available in `models/`, and the input `.npy` files are present in `test_images/`.

The training process included:

- Dataset loading

- Model initialization
- FP32 training
- Validation
- Loss calculation
- Learning-rate scheduling
- Checkpoint saving
- Best-model selection

The training configuration was:

- **Model:** HLSRestorationNet
- **Training epochs:** 30
- **Batch size:** 8
- **Optimizer:** AdamW
- **Learning rate:** `1e-4`
- **Weight decay:** `1e-4`
- **Loss:** `0.8 × L1 + 0.2 × SSIM loss`
- **Validation split:** 90% training / 10% validation
- **Random state:** 42
- **Scheduler:** ReduceLROnPlateau

```

The INT8 QAT checkpoint is provided as:

```

## Dataset

The model was trained using the project's paired image restoration dataset containing degraded low-resolution (`NoisyLR`) images and corresponding ground-truth (`GT`) images.

```

```

The `NoisyLR/` directory contains degraded input images, while the `GT/` directory contains the corresponding ground-truth restored images.

Each input and ground-truth file must have a matching filename stem.

Example:

```
NoisyLR/
└── sample_001.npy

GT/
└── sample_001.npy

```

The original training workflow uses a deterministic **90% training / 10% validation split** with `random_state=42`.

The model expects **128 × 128** input images and corresponding **256 × 256** ground-truth images.

## Preprocessing

The input data is provided as `.npy` arrays.

The preprocessing pipeline includes:

1. Loading the `.npy` array using NumPy.
2. Converting the array to `float32`.
3. Converting the NumPy array to a PyTorch tensor.
4. Adding the channel dimension.
5. Passing the resulting tensor to the restoration model.

No additional normalization is applied by the dataset preprocessing pipeline beyond the value range already present in the source data.

The model expects a **1 × 128 × 128 grayscale input**.

## Postprocessing

The restoration model generates a **1 × 256 × 256** output.

The final sigmoid activation produces output values in the expected `[0, 1]` range.

The model output is converted back into the required NumPy representation and saved as a `.npy` file in the `output/` directory.
